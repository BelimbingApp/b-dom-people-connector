# Connection backup and recovery

Connection managers open **Backup and recovery** from People connection health,
at `/integrations/people/backups`. Every operation validates the authenticated
actor, active platform company and tenant. Only the co-located native provider
is supported. Remote and vendor transport remain disabled.

Back up a configured connection when no sync is running. The private JSON
snapshot contains its provider contract, platform/workforce mapping, enabled
state, non-secret sync/file/webhook policy, checkpoint cursor/time and all
Connector directory projections, including inactive records. It contains no
People business tables, credentials, webhook signing secrets, audit history,
sync outcomes, reconciliation history or replay guards. Backup receipts retain
provenance and a SHA-256 bound to the generated bytes. Failed publication leaves
a failed receipt; Base Artifacts owns private bytes, integrity checks and
cleanup tombstones.

Provision private Base Artifacts storage and retention in Operator Settings
first. Backup retention and preview validity are company settings, editable
inline on this page. Each backup captures its expiry at creation, capped by
Base Artifacts' installation retention. Changing policy affects new backups.
Expired backups cannot be previewed/restored. **Clean expired backups** deletes
private bytes through Base Artifacts; receipts and audit remain, and a cleaned
receipt keeps its artifact reference with the `purged` state. Each run takes the
next batch, bounded by the installation artifact batch setting. A failed delete
records its attempt count, reason and time on the receipt and
`people-connector.backup.purge_failed`; cleanup skips it until the artifact
purge retry interval passes, so newer expired backups are still reached. After
the artifact purge maximum attempts it is held (`people-connector.backup.purge_held`),
excluded from batches and listed under **Held cleanup**; **Retry cleanup**
releases the hold (`people-connector.backup.purge_released`) and deletes again.
Retry interval and maximum attempts are Base Artifacts' installation settings.
Artifacts' generic cleanup also handles incomplete storage reservations.

## Guarded restore

1. Select **Preview restore**. The server reads and integrity-checks the
   artifact, validates its tenant/company, format, connection and native mapping,
   and records a random confirmation token bound to the current actor (including
   impersonation), connection state and preview expiry.
2. Review before/after configuration, checkpoint and directory counts. The
   preview states that directory contents and checkpoint cursor will be replaced.
3. Choose **Restore backup**, then confirm in the shared confirmation dialog.
   The server rechecks authorization, bytes, mapping, idle sync state and the
   reviewed state fingerprint under the connection lock. A changed/expired
   preview must be regenerated.

Restore replaces Connector-owned projections and checkpoint state atomically
with non-secret settings and enabled state. Checkpoint generation advances
rather than rolling backward, so late sync results cannot apply against the
restored cursor. Excluded credentials and webhook secrets are cleared; webhook
intake is disabled. Re-enter secrets with the existing secret input on People
connections before enabling webhook intake. Native directory reads need no
credential.

A backup can be restored once. Repeating its exact confirmed request returns
the recorded restore without applying changes again, even after later syncs.
A different actor/token is refused. Requesting another preview invalidates the
previous token. A backup from a removed/recreated connection or changed mapping
cannot be restored into the new identity: create a new native backup after
configuration. Backup does not recreate removed connections or modify People
records.

## Recovery

After restore, **Sync from checkpoint** calls the ordinary native sync engine
with the restored checkpoint generation and a backup-specific idempotency key.
The sync starts only if that generation is still current. If an intervening
sync moved it, use normal synchronisation from People connections. Repeating a
recovery request returns its recorded run and does not execute another pass.
A backup with no checkpoint recovers by bootstrap. If restored configuration
was disabled, enable the connection on People connections before recovery.
Review connection health for failed, unavailable or unknown outcomes; recovery
never claims completion without a successful recorded sync.

Backup creation, preview, restore, replay and recovery requests record operator
actions with IDs only, including impersonator identity. Artifact access/deletion
is audited by Base. Audit/storage failures refuse publication or roll back
restore. No bytes, personal directory facts, cursor or secret enter action
payloads.

The public workflow is `Connector.Backup`: `summary/2`, `configure/3`,
`create/2`, `preview/3`, `restore/5`, `recover/3`, `purge_expired/2`,
`retry_purge/3`.
Company arguments are Core platform company IDs; each method takes a validated
Tenancy Scope. Schema and artifact adapters remain internal to this module.

`Backup.SchemaContract` verifies the fresh receipt table after migration. It is
kept out of baseline adoption, which runs before pending Bilimbi-only tables
exist. Its executable verifier test covers columns, indexes, foreign keys and
the receipt-state constraint.
